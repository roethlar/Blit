## Goal

Close the six correctness, data-safety, and path-containment defects (`af-1..af-6`) uncovered by the 2026-10-20 codebase audit so that:

1. `blit move`, `blit copy`, and `blit mirror` refuse identical or invalid overlapping source and destination roots before touching the filesystem or initiating a remote transfer.
2. Nested local destination self-copy exclusion (`dest_subtree_rel`) resolves relative, symlinked, and case-varied paths and prunes the destination subtree during `FsTransferSource` directory enumeration rather than only filtering headers after walking the destination on disk.
3. `MirrorPlanner::plan_session_deletions` preserves synced and shielded destination entries whose on-disk spelling differs from the source in non-ASCII Unicode case or Unicode normalization (NFC/NFD, `σ`/`ς`, `ß`/`SS`) on Windows, macOS, and case-insensitive mounts.
4. `DelegatedPull` validates `dst_destination_path` through `resolve_relative_path` (`validate_wire_path`), and `verify_contained` / `canonical_dest_root` reject any target relative path containing `..` components before walking ancestors.
5. `DirStatCache::lookup` on Unix/macOS never returns a false `DirStatLookup::Absent` when a non-ASCII lookup name misses `exact` and `folded` in a directory containing non-ASCII entries (such as NFC vs. NFD filenames on APFS).
6. `FileFilter::is_empty()` accounts for `self.destination`, ensuring `MirrorPlanner::plan_session_deletions` runs `keep_dirs_holding_left_out_entries` on `--exclude`-only `MirrorMode::FilteredSubset` runs (including `--dry-run`).

## Non-goals

- Wire protocol or `CONTRACT_VERSION` changes: all six fixes are local to CLI endpoint validation, daemon request validation, source enumeration, destination stat caching, and mirror deletion planning.
- Changing the intentional `blit copy` behavior where copying a directory into a newly created or existing subdirectory of itself (`blit copy /a/dir /a/dir/backup`) succeeds while excluding `backup` from the source walk.

## Constraints

- **One finding per commit** (`AGENTS.md`): each slice `af-1..af-6` lands in its own commit with its own mutation-proven regression test (revert the production fix, observe the new test fail, restore).
- **Zero performance regression on the common path** (FAST, D-2026-07-09-1):
  - `af-3` (`MirrorPlanner` identity pairing) must perform zero extra `symlink_metadata` / `GetFileInformationByHandle` calls when all source files match `dest_entries` by exact path or `CasefoldKey`, or when no deletions are planned.
  - `af-5` (`DirStatCache` non-ASCII fallback) must keep trusted `DirStatLookup::Absent` for all ASCII lookups and all ASCII-only directories, and must keep `DirStatLookup::Entry` cache hits when non-ASCII filenames have matching byte sequences.

## Acceptance criteria

- [ ] **AC-1 (`af-1`)**: `blit move <src> <dst>` refuses before transferring or deleting anything when `src` and resolved `dst` refer to the same path (e.g. `blit move /a/dir /a --yes` where `/a` is an existing directory, so `resolve_destination` yields `/a/dir`), when `dst` is a descendant of `src` (`blit move /a/dir /a/dir/sub --yes`), or when `dst` is an ancestor of `src`. `blit copy` and `blit mirror` also refuse when `src` and resolved `dst` are identical or when `dst` is an ancestor of `src`. Remote-to-remote delegated `move` refuses when source and destination resolve to the same host, port, module, and equal or overlapping paths.
- [ ] **AC-2 (`af-2`)**: `blit copy ./src src/backup` (mixed `./` prefix, relative vs. absolute, or symlinked ancestor) detects that `src/backup` is inside `./src`, does not copy `src/backup` into `src/backup/backup`, and prunes `backup` during `FsTransferSource` directory traversal without recording `backup` as a user `--exclude` in `pruned_paths`.
- [ ] **AC-3 (`af-3`)**: `MirrorPlanner::plan_session_deletions` does not plan for deletion any destination file or directory whose on-disk name is paired by the destination filesystem with a kept source path (`source_files` or `raw_entries`) or a failed transfer path (`shielded`), including non-ASCII Unicode case pairs (`Übung` vs. `übung`, `σ` vs. `ς`) and APFS NFC/NFD pairs (`caf\u{e9}.txt` vs. `cafe\u{301}.txt`).
- [ ] **AC-4 (`af-4`)**: `run_delegated_pull` rejects `DelegatedPullRequest.dst_destination_path` values containing `..`, absolute paths, Windows drive/UNC prefixes, or NUL bytes via `resolve_relative_path` before connecting to the source daemon, and `path_safety::verify_contained` / `canonical_dest_root` reject any path containing `Component::ParentDir` (`..`) even when preceded by a non-existent directory component (`nonexistent/../../outside`).
- [ ] **AC-5 (`af-5`)**: `DirStatCache::lookup` returns `DirStatLookup::Fallback` (never `DirStatLookup::Absent`) when a non-ASCII filename misses `exact` and `folded` in a directory that contains at least one non-ASCII entry, preserving `--ignore-existing` and `SizeMtime` convergence for NFC/NFD-mismatched files on macOS APFS.
- [ ] **AC-6 (`af-6`)**: `FileFilter::is_empty()` returns `false` when `self.destination.is_some()`, so `MirrorPlanner::plan_session_deletions` invokes `keep_dirs_holding_left_out_entries` on `--exclude`-only `MirrorMode::FilteredSubset` runs and `blit mirror --exclude ... --dry-run` does not count directories holding excluded entries as deleted.

## Design

### Slice `af-1`: Source/destination root disjointness and overlap validation

- **Files**:
  - `crates/blit-core/src/transfers/resolution.rs`
  - `crates/blit-core/src/transfer_session/local.rs`
  - `crates/blit-cli/src/transfers/mod.rs`
- **Mechanism**:
  1. Add `canonical_target_path(path: &Path) -> Result<PathBuf>` in `crates/blit-core/src/transfers/resolution.rs`:
     - Normalize `path` lexically via `std::path::absolute(path)` and collapse `.` / `..` components so relative forms (`./dir`, `dir/../dir`) become clean absolute paths before touching the filesystem.
     - Walk up from the normalized path to the deepest existing ancestor (collecting popped `Normal` tail components), call `std::fs::canonicalize` on that existing ancestor, and re-append the popped tail components in order.
  2. Add `validate_local_transfer_roots(src_root: &Path, dst_root: &Path, is_move: bool) -> Result<Option<PathBuf>>`:
     - Compute `canon_src = canonical_target_path(src_root)?` and `canon_dst = canonical_target_path(dst_root)?`.
     - Compare components using OS-appropriate comparison (exact `OsStr` on Linux; case-folded on Windows/macOS for non-existent tail components, since `std::fs::canonicalize` already normalizes existing components to their on-disk form; plus `entry_identity` equality when both `src_root` and `dst_root` exist on disk).
     - If `canon_src == canon_dst`: bail `"source and destination resolve to the same path: '{}'"`.
     - If `canon_src` is a strict descendant of `canon_dst`: bail `"destination '{}' contains source '{}'"`.
     - If `canon_dst` is a strict descendant of `canon_src` with relative tail `rel`:
       - If `is_move`: bail `"cannot move '{}' into a subdirectory of itself, '{}'"`.
       - Otherwise: return `Ok(Some(rel))`.
     - Otherwise: return `Ok(None)`.
  3. Call `validate_local_transfer_roots(&src_path, &dst_path, true)` at the start of `TransferPlan::LocalToLocal` in `run_move_inner` (`crates/blit-cli/src/transfers/mod.rs:823`) before the confirmation prompt or `run_local_transfer`, and call `validate_local_transfer_roots(&src_root, &dst_root, false)` inside `run_local_transfer` (`crates/blit-core/src/transfer_session/local.rs:795`) so `copy`, `mirror`, and direct library callers of `run_local_transfer` also reject `src == dst` and `dst` containing `src`.
  4. In `run_move_inner` (`crates/blit-cli/src/transfers/mod.rs:1126`, `TransferPlan::RemoteToRemoteDelegated`), check whether `src_ep` and `dst_ep` target the same host (case-insensitive) and port and the same module (`RemotePath::Module` / `RemotePath::Root`), and if so, normalize `src_rel` and `dst_rel` (`dst_rel` after `resolve_destination` semantics when `dst_rel` is a container/trailing-slash) and bail if `src_rel == dst_rel` or one is a prefix of the other.

### Slice `af-2`: Canonical `dest_subtree_rel` and pre-walk pruning in `FsTransferSource`

- **Files**:
  - `crates/blit-core/src/transfer_session/local.rs`
  - `crates/blit-core/src/remote/transfer/source.rs`
  - `crates/blit-core/src/enumeration.rs`
- **Mechanism**:
  1. Replace the raw lexical `dest_subtree_rel(src_root, dst_root)` in `crates/blit-core/src/transfer_session/local.rs:711-716` with the relative path returned by `validate_local_transfer_roots(&src_root, &dst_root, false)?`.
  2. Add `with_excluded_subtree(mut self, rel: PathBuf) -> Self` on `FsTransferSource` (`crates/blit-core/src/remote/transfer/source.rs`) and `FileEnumerator` (`crates/blit-core/src/enumeration.rs`).
  3. In `FileEnumerator`'s walk loop, skip any entry whose `relative_path == excluded_subtree` or starts with `excluded_subtree` (`continue` before descending into directories or emitting entries), **without** pushing the skipped path to `pruned_paths` (so `mirror_delete_pass` on `dst_root` is unaffected). Keep `DestSubtreeExcludedSource` in `local.rs` as defense-in-depth on the channel.

### Slice `af-3`: Unicode case and filesystem-identity pairing in `MirrorPlanner::plan_session_deletions`

- **Files**:
  - `crates/blit-core/src/mirror_planner.rs`
  - `crates/blit-core/src/transfers/filter.rs`
- **Mechanism**:
  1. Expose `pub(crate) fn entry_identity(path: &Path) -> Option<((u64, u64), u64)>` from `crates/blit-core/src/transfers/filter.rs` (already implemented for `#[cfg(unix)]`, `#[cfg(windows)]`, and `#[cfg(not(any(unix, windows)))]` at lines 706–752).
  2. In `crates/blit-core/src/mirror_planner.rs`:
     - Update `CasefoldKey::new` on `#[cfg(any(windows, target_os = "macos"))]` to use `.to_lowercase()` instead of `.to_ascii_lowercase()`, so standard Unicode case differences (`Ü` vs. `ü`, `É` vs. `é`) fold to the same key in memory without syscalls.
     - In `MirrorPlanner::plan_session_deletions`:
       - Retain the original relative `PathBuf` alongside each `CasefoldKey` in `source_paths: HashMap<CasefoldKey, PathBuf>` and `shield_paths: HashMap<CasefoldKey, PathBuf>`.
       - During the initial pass over `dest_entries`, mark which `CasefoldKey`s in `source_paths` and `shield_paths` were matched directly by `CasefoldKey::new(&rel)`.
       - If any `dest_entries` remain as deletion candidates AND `source_paths` or `shield_paths` has unmatched entries:
         - Compute `entry_identity(&dest_root.join(unmatched_path))` for the unmatched `source_paths` (storing their `((u64, u64))` identities in `kept_identities: HashSet<(u64, u64)>`) and for unmatched `shield_paths` (storing their identities in `shield_identities: HashSet<(u64, u64)>`).
         - For each unmatched `dest_entry` `(rel, is_dir)`:
           - Look up `entry_identity(&dest_root.join(&rel))`.
           - If its identity is in `shield_identities`, insert `CasefoldKey::new(&rel)` into `shield_set` so `is_shielded` protects `rel` and all its descendants.
           - If its identity is in `kept_identities`, keep `rel` and insert `CasefoldKey::new` for `rel` and each of its parent components into `source_set` so neither `rel` nor its ancestor directories on disk are deleted.

- **Files**:
  - `crates/blit-daemon/src/service/delegated_pull.rs`
  - `crates/blit-core/src/path_safety.rs`
- **Mechanism**:

In `crates/blit-daemon/src/service/delegated_pull.rs:347-355` (`run_delegated_pull`), replace `PathBuf::from(&req.dst_destination_path)` with `super::util::resolve_relative_path(&req.dst_destination_path)` (mapping `Err(status)` to `phased_error(Phase::DelegationRejected as i32, status.message().to_string())` and performing the syntax check in Step 2 right after `validate_spec`, before DNS resolution in Step 3).
  2. In `crates/blit-core/src/path_safety.rs`, harden `verify_contained` (line 273) and `canonical_dest_root` (line 347):

     - In `canonical_dest_root(dest_root)`, normalize `dest_root` or reject `Component::ParentDir` after `std::path::absolute` before walking `probe.pop()`.

### Slice `af-5`: `DirStatCache` non-ASCII fallback on Unix/macOS

- **Files**:
  - `crates/blit-core/src/transfer_session/dir_stat.rs`
- **Mechanism**:
  1. Add `has_non_ascii: bool` to `DirSnapshot::Swept { exact, folded, has_non_ascii }`.
  2. In `sweep_directory`, set `has_non_ascii |= !file_name.as_encoded_bytes().is_ascii()` for each entry read from `std::fs::read_dir(dir)`.
  3. In `DirStatCache::lookup` (lines 221–244), add an arm before `#[cfg(not(windows))] None => DirStatLookup::Absent`:
     ```rust
     None if *has_non_ascii && !name.as_encoded_bytes().is_ascii() => DirStatLookup::Fallback,
     ```
     so any non-ASCII lookup name that misses `exact` and `folded` in a directory holding non-ASCII entries falls back to `symlink_metadata`, letting the OS filesystem resolve NFC/NFD or non-ASCII case equivalence.

## Slices

1. **`af-1`**: Reject identical or invalid overlapping source and destination roots in `move`, `copy`, and `mirror` (`resolution.rs`, `local.rs`, `transfers/mod.rs`).
2. **`af-2`**: Normalize `dest_subtree_rel` via `canonical_target_path` and prune the nested destination subtree during `FsTransferSource` / `FileEnumerator` traversal (`local.rs`, `source.rs`, `enumeration.rs`).
3. **`af-3`**: Pair destination entries by Unicode lowercase `CasefoldKey` and on-disk `entry_identity` fallback in `MirrorPlanner::plan_session_deletions` (`mirror_planner.rs`, `transfers/filter.rs`).
4. **`af-4`**: Validate `dst_destination_path` via `resolve_relative_path` in `DelegatedPull` and reject `Component::ParentDir` in `verify_contained` (`delegated_pull.rs`, `path_safety.rs`).
5. **`af-5`**: Fall back to `symlink_metadata` in `DirStatCache::lookup` when a non-ASCII name misses `exact` and `folded` in a directory with non-ASCII entries (`dir_stat.rs`).
6. **`af-6`**: Check `self.destination.is_none()` in `FileFilter::is_empty()` so `keep_dirs_holding_left_out_entries` runs on `--exclude`-only mirror deletion plans (`fs_enum.rs`, `mirror_planner.rs`).
