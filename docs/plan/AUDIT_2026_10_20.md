# Codebase Audit Fixes (2026-10-20)

**Status**: Active — owner: "a" (2026-10-20, D-2026-10-20-1), after r1 and r2 Claude review changes were adopted (`plan-audit-2026-10-20-r1..r2`)
**Created**: 2026-10-20

**Decision ref**: D-2026-10-20-1

## Goal

Close the five confirmed correctness, data-safety, and path-containment defects (`af-1..af-5`) uncovered by the 2026-10-20 codebase audit so that:

1. `blit move`, `blit copy`, and `blit mirror` refuse identical or invalid overlapping source and destination roots in `prepare_transfer_route` before printing banners, prompting for destructive confirmation, touching the filesystem, or initiating a remote transfer (with `run_local_session` enforcing the same invariant for direct `blit-core` library callers).
2. Nested local destination self-copy exclusion (`dest_subtree_rel`) resolves relative, symlinked, and case-varied paths via the shared deepest-existing-ancestor canonicalization in `path_safety` and prunes the destination subtree during `FsTransferSource` directory enumeration rather than only filtering headers after walking the destination on disk.
3. `MirrorPlanner::plan_session_deletions` preserves synced and shielded destination entries whose on-disk spelling differs from the source in non-ASCII Unicode case or Unicode normalization (NFC/NFD, `σ`/`ς`, `ß`/`SS`) on Windows and macOS.
4. `DelegatedPull` validates `dst_destination_path` through `resolve_relative_path` (`validate_wire_path`), and `verify_contained` / `canonical_dest_root` reject any target path containing `..` components before walking ancestors.
5. `DirStatCache::lookup` on Unix/macOS never returns a false `DirStatLookup::Absent` when a non-ASCII lookup name misses `exact` and `folded` in a directory containing non-ASCII entries (such as NFC vs. NFD filenames on APFS).

## Non-goals

- Wire protocol or `CONTRACT_VERSION` changes: all five fixes are local to CLI endpoint validation, daemon request validation, source enumeration, destination stat caching, and mirror deletion planning.
- Changing the intentional `blit copy` behavior where copying a directory into a newly created or existing subdirectory of itself (`blit copy /a/dir /a/dir/backup`) succeeds while excluding `backup` from the source walk.
- Modifying `FileFilter::is_empty()` (dropped after `plan-audit-2026-10-20-r1` F1 confirmed `destination_scope` at `crates/blit-core/src/transfers/filter.rs:822` only populates `destination` when `exclude_files` or `pruned` is non-empty, and `pruned` only arises from exclude rules at `crates/blit-core/src/enumeration.rs:45-54`, so `is_empty()` is already `false` whenever `destination.is_some()` in production).
- ASCII case-folding in `MirrorPlanner` on Linux case-insensitive mounts (`ext4` `casefold` / VFAT): `CasefoldKey` remains exact `PathBuf` on `#[cfg(not(any(windows, target_os = "macos")))]` (`crates/blit-core/src/mirror_planner.rs:67`), while the directory-scoped `entry_identity` fallback in `af-3` covers directories containing non-ASCII unmatched source, shield, or destination entries on all platforms.

## Constraints

- **One finding per commit** (`AGENTS.md`): each slice `af-1..af-5` lands in its own commit with its own mutation-proven regression test (revert the production fix, observe the new test fail, restore).
- **Zero performance regression on the common path, including `--dry-run` and first sync** (FAST, D-2026-07-09-1):
  - `af-3` (`MirrorPlanner` identity pairing) must not issue O(sources) `entry_identity` syscalls when `mirror_delete_pass` runs on `--dry-run` or on a first sync where most source paths do not yet exist at the destination (`crates/blit-core/src/transfer_session/mod.rs:4097-4110`). Standard Unicode case differences (`Ü` vs. `ü`, `σ` vs. `ς`) are folded in memory via `.to_lowercase()` in `CasefoldKey::new`, and the on-disk `entry_identity` fallback is gated by **candidate parent directories** (`candidate_parent_dirs`: parent directories that hold both at least one unmatched destination candidate and at least one unmatched source/shield path, where at least one side in that directory is non-ASCII). Within those candidate directories, every unmatched source/shield path and every unmatched destination candidate (including ASCII destination spellings such as `bSS` paired with `bß`) is probed. Any pure-ASCII tree, synced tree, or dry run where no directory has both an unmatched entry and a non-ASCII unmatched counterpart performs zero `entry_identity` syscalls.
  - `af-5` (`DirStatCache` non-ASCII fallback) must keep trusted `DirStatLookup::Absent` for all ASCII lookups and all ASCII-only directories, and must keep `DirStatLookup::Entry` cache hits when non-ASCII filenames have matching byte sequences.

## Acceptance criteria

- [ ] **AC-1 (`af-1`)**: `blit move <src> <dst>` refuses inside `prepare_transfer_route` — before printing the `starting ...` banner, prompting `confirm_destructive_operation`, transferring, or deleting anything — when `src` and resolved `dst` refer to the same path (e.g. `blit move /a/dir /a` where `/a` is an existing directory, so `resolve_destination` yields `/a/dir`), when `dst` is a descendant of `src` (`blit move /a/dir /a/dir/sub`), or when `dst` is an ancestor of `src`. `blit copy` and `blit mirror` (and direct library callers of `blit_core::transfer_session::run_local_session` / `blit_core::transfers::local::run`) also refuse before prompting or transferring when `src` and resolved `dst` are identical or when `dst` is an ancestor of `src`. Remote-to-remote delegated `move` refuses in `prepare_transfer_route` before prompting when source and destination resolve to the same host, port, module, and equal or overlapping paths.
- [ ] **AC-2 (`af-2`)**: `blit copy ./src src/backup` (mixed `./` prefix, relative vs. absolute, or symlinked ancestor) detects that `src/backup` is inside `./src`, does not copy `src/backup` into `src/backup/backup`, and prunes `backup` during `FsTransferSource` directory traversal without recording `backup` as a user `--exclude` in `pruned_paths`.
- [ ] **AC-3 (`af-3`)**: `MirrorPlanner::plan_session_deletions` does not plan for deletion any destination file or directory whose on-disk name is paired by the destination filesystem with a kept source path (`source_files` or `raw_entries`) or a failed transfer path (`shielded`), including non-ASCII Unicode case pairs (`Übung` vs. `übung`, `σ` vs. `ς`), multi-character case folds where the destination spelling is ASCII (`bß` vs. `bSS`), and APFS NFC/NFD pairs (`caf\u{e9}.txt` vs. `cafe\u{301}.txt`), while performing zero `entry_identity` syscalls on pure-ASCII trees.
- [ ] **AC-4 (`af-4`)**: `run_delegated_pull` rejects `DelegatedPullRequest.dst_destination_path` values containing `..`, absolute paths, Windows drive/UNC prefixes, or NUL bytes via `resolve_relative_path` before connecting to the source daemon, and `path_safety::verify_contained` / `canonical_dest_root` reject any path containing `Component::ParentDir` (`..`) even when preceded by a non-existent directory component (`nonexistent/../../outside`).
- [ ] **AC-5 (`af-5`)**: On non-Windows targets (`#[cfg(not(windows))]`), `DirStatCache::lookup` returns `DirStatLookup::Fallback` (never `DirStatLookup::Absent`) when a non-ASCII filename misses `exact` and `folded` in a directory that contains at least one non-ASCII entry, preserving `--ignore-existing` and `SizeMtime` convergence for NFC/NFD-mismatched files on macOS APFS and compiling cleanly under `-D warnings` on all platforms.

## Design

### Slice `af-1`: Source/destination root disjointness and overlap validation

- **Files**:
  - `crates/blit-core/src/path_safety.rs`
  - `crates/blit-core/src/transfers/resolution.rs`
  - `crates/blit-core/src/transfer_session/local.rs`
  - `crates/blit-cli/src/transfers/mod.rs`
- **Mechanism**:
  1. Reuse and extend the deepest-existing-ancestor canonicalization in `crates/blit-core/src/path_safety.rs:347-370` (`canonical_dest_root`) into a shared helper `canonical_target_path(path: &Path) -> Result<PathBuf>` exported from `path_safety`:
     - Obtain an absolute path via `std::path::absolute(path)` **without** collapsing `..` lexically first, so `std::fs::canonicalize` resolves symlinks followed by `..` on disk over the existing prefix.
     - Walk up from the path to the deepest existing ancestor, call `std::fs::canonicalize` on that existing ancestor, and re-append the non-existent tail components while resolving `.` and rejecting any `Component::ParentDir` (`..`) that sits in the non-existent tail above the existing ancestor.
  2. Add `validate_local_transfer_roots(src_root: &Path, dst_root: &Path, is_move: bool) -> Result<Option<PathBuf>>` in `crates/blit-core/src/transfers/resolution.rs`:
     - Compute `canon_src = canonical_target_path(src_root)?` and `canon_dst = canonical_target_path(dst_root)?`.
     - Compare components using OS-appropriate comparison (exact `OsStr` on Linux; Unicode case-folded on Windows/macOS for non-existent tail components, since `std::fs::canonicalize` already normalizes existing components to their on-disk form; plus `entry_identity` equality when both `src_root` and `dst_root` exist on disk).
     - If `canon_src == canon_dst`: bail `"source and destination resolve to the same path: '{}'"`.
     - If `canon_src` is a strict descendant of `canon_dst`: bail `"destination '{}' contains source '{}'"`.
     - If `canon_dst` is a strict descendant of `canon_src` with relative tail `rel`:
       - If `is_move`: bail `"cannot move '{}' into a subdirectory of itself, '{}'"`.
       - Otherwise: return `Ok(Some(rel))`.
     - Otherwise: return `Ok(None)`.
  3. Anchor CLI validation in `prepare_transfer_route` (`crates/blit-cli/src/transfers/mod.rs:170`), which is called by both `run_transfer_inner` (:242) and `run_move_inner` (:659) before any flag gate, `starting ...` banner, or `confirm_destructive_operation` prompt (:347, :802):
     - For `TransferRoute::LocalToLocal { src, dst, .. }`: call `validate_local_transfer_roots(src, dst, matches!(mode, TransferKind::Move))?`.
     - For `TransferRoute::RemoteToRemoteDelegated { src, dst }` when `matches!(mode, TransferKind::Move)`: check whether `src` and `dst` target the same host (case-insensitive), port, and module (`RemotePath::Module` / `RemotePath::Root`), and if so, normalize `src_rel` and `dst_rel` and bail if `src_rel == dst_rel` or one is a prefix of the other.
  4. Also call `validate_local_transfer_roots(src_root, dst_root, false)` at the start of `run_local_session` (`crates/blit-core/src/transfer_session/local.rs:722`) as the backstop for direct `blit-core` library callers (`run_local_session` / `blit_core::transfers::local::run`).

### Slice `af-2`: Canonical `dest_subtree_rel` and pre-walk pruning in `FsTransferSource`

- **Files**:
  - `crates/blit-core/src/transfer_session/local.rs`
  - `crates/blit-core/src/remote/transfer/source.rs`
  - `crates/blit-core/src/enumeration.rs`
- **Mechanism**:
  1. Replace the raw lexical `dest_subtree_rel(src_root, dst_root)` in `crates/blit-core/src/transfer_session/local.rs:711-716` with the relative path returned by `validate_local_transfer_roots(src_root, dst_root, false)?`.
  2. Add `with_excluded_subtree(mut self, rel: PathBuf) -> Self` on `FsTransferSource` (`crates/blit-core/src/remote/transfer/source.rs`) and `FileEnumerator` (`crates/blit-core/src/enumeration.rs`).
  3. In `FileEnumerator`'s walk loop, skip any entry whose `relative_path == excluded_subtree` or starts with `excluded_subtree` (`continue` before descending into directories or emitting entries), **without** pushing the skipped path to `pruned_paths` (so `mirror_delete_pass` on `dst_root` is unaffected). Keep `DestSubtreeExcludedSource` in `local.rs` as defense-in-depth on the channel.

### Slice `af-3`: Unicode case and directory-scoped filesystem-identity pairing in `MirrorPlanner::plan_session_deletions`

- **Files**:
  - `crates/blit-core/src/mirror_planner.rs`
  - `crates/blit-core/src/transfers/filter.rs`
- **Mechanism**:
  1. Expose `pub(crate) fn entry_identity(path: &Path) -> Option<((u64, u64), u64)>` from `crates/blit-core/src/transfers/filter.rs` (already implemented for `#[cfg(unix)]`, `#[cfg(windows)]`, and `#[cfg(not(any(unix, windows)))]` at lines 706–752).
  2. In `crates/blit-core/src/mirror_planner.rs`:
     - Update `CasefoldKey::new` on `#[cfg(any(windows, target_os = "macos"))]` to use `.to_lowercase()` instead of `.to_ascii_lowercase()`, so standard Unicode case differences (`Ü` vs. `ü`, `É` vs. `é`, `σ` vs. `ς`) fold to the same key in memory without syscalls.
     - In `MirrorPlanner::plan_session_deletions`:
       - During the initial pass over `dest_entries`, collect unmatched deletion candidates `unmatched_dest: Vec<(PathBuf, bool)>` and track which `CasefoldKey`s in `source_set` and `shield_set` were matched.
       - Gate the on-disk `entry_identity` fallback by **parent directory** rather than filtering individual destination filenames by ASCII-ness (so APFS `bß` source vs. `bSS` ASCII destination is reached while pure-ASCII trees still perform 0 syscalls):
         - Group unmatched `source_paths` / `shield_paths` and `unmatched_dest` entries by their parent directory's `CasefoldKey` (`CasefoldKey::new(rel.parent().unwrap_or(Path::new("")))`).
         - Select `candidate_parent_dirs`: parent directories that have **both** at least one `unmatched_dest` entry **and** at least one unmatched source/shield path, where at least one of those unmatched entries in the directory contains non-ASCII bytes (`!rel.as_os_str().as_encoded_bytes().is_ascii()`).
         - If `candidate_parent_dirs` is empty, skip the identity pass completely (0 syscalls).
         - For each directory in `candidate_parent_dirs`, compute `entry_identity(&dest_root.join(src_rel))` for its unmatched source/shield paths (storing `(dev, ino)` / file-index identities in `kept_identities` and `shield_identities`), and then for every `unmatched_dest` entry `(rel, is_dir)` in that directory (whether `rel` itself is ASCII like `bSS` or non-ASCII), look up `entry_identity(&dest_root.join(&rel))`:
           - If in `shield_identities`, insert `CasefoldKey::new(&rel)` into `shield_set` so `is_shielded` protects `rel` and all its descendants.
           - If in `kept_identities`, retain `rel` and insert `CasefoldKey::new` for `rel` and each of its ancestor directories into `source_set` so neither `rel` nor its parent directories are deleted.

### Slice `af-4`: `DelegatedPull` wire-path validation and `verify_contained` `..` hardening

- **Files**:
  - `crates/blit-daemon/src/service/delegated_pull.rs`
  - `crates/blit-core/src/path_safety.rs`
- **Mechanism**:
  1. In `crates/blit-daemon/src/service/delegated_pull.rs:347-355` (`run_delegated_pull`), replace `PathBuf::from(&req.dst_destination_path)` with `super::util::resolve_relative_path(&req.dst_destination_path)` (mapping `Err(status)` to `phased_error(Phase::DelegationRejected as i32, status.message().to_string())` and performing the syntax check in Step 2 right after `validate_spec`, before DNS resolution in Step 3).
  2. In `crates/blit-core/src/path_safety.rs`, harden `verify_contained` (line 273) and `canonical_dest_root` (line 347):
     - In `verify_contained(canonical_module_root, target)`, reject `target` immediately if `target.components().any(|c| matches!(c, Component::ParentDir))` (`bail!("path '{}' contains '..' component", target.display())`), before entering the `probe.pop()` canonicalization loop.
     - In `canonical_dest_root(dest_root)` (and the shared `canonical_target_path` helper from `af-1`), reject any `Component::ParentDir` that remains in the non-existent tail after `std::path::absolute` so `nonexistent/../../outside` cannot pop past `nonexistent` into a passing ancestor.

### Slice `af-5`: `DirStatCache` non-ASCII fallback on Unix/macOS

- **Files**:
  - `crates/blit-core/src/transfer_session/dir_stat.rs`
- **Mechanism**:
  1. Add `#[cfg(not(windows))] has_non_ascii: bool` to `DirSnapshot::Swept`.
  2. In `sweep_directory`, under `#[cfg(not(windows))]`, set `has_non_ascii |= !file_name.as_encoded_bytes().is_ascii()` for each entry read from `std::fs::read_dir(dir)`.
  3. In `DirStatCache::lookup` (`crates/blit-core/src/transfer_session/dir_stat.rs:240-244`), replace the `#[cfg(not(windows))] None => DirStatLookup::Absent` arm with:
     ```rust
     #[cfg(not(windows))]
     None if *has_non_ascii && !name.as_encoded_bytes().is_ascii() => {
         DirStatLookup::Fallback
     }
     #[cfg(not(windows))]
     None => DirStatLookup::Absent,
     ```
     so Windows continues to use its existing `#[cfg(windows)] None => DirStatLookup::Fallback` arm without an `unreachable_patterns` warning under `-D warnings`, while Unix/macOS falls back to `symlink_metadata` when a non-ASCII lookup name misses `exact` and `folded` in a directory holding non-ASCII entries.

1. **`af-1`**: Reject identical or invalid overlapping source and destination roots in `prepare_transfer_route` and `run_local_session` (`path_safety.rs`, `resolution.rs`, `transfer_session/local.rs`, `transfers/mod.rs`).

3. **`af-3`**: Pair destination entries by Unicode lowercase `CasefoldKey` and directory-scoped `entry_identity` fallback in `MirrorPlanner::plan_session_deletions` (`mirror_planner.rs`, `transfers/filter.rs`).
4. **`af-4`**: Validate `dst_destination_path` via `resolve_relative_path` in `DelegatedPull` and reject `Component::ParentDir` in `verify_contained` / `canonical_dest_root` (`delegated_pull.rs`, `path_safety.rs`).
5. **`af-5`**: Fall back to `symlink_metadata` under `#[cfg(not(windows))]` in `DirStatCache::lookup` when a non-ASCII name misses `exact` and `folded` in a directory with non-ASCII entries (`dir_stat.rs`).
