## Evidence
crates/blit-core/src/transfers/filter.rs:1299 — fold retains characters with multi-character uppercase mappings and changes candidate byte lengths through NFC and uppercase conversion. The folded matcher assembled at line 1015 therefore does not preserve globset's byte-width wildcard semantics or all filesystem equivalences. On macOS APFS, mirror --exclude '*ß' excluded src/aß but deleted dst/aSS/saved.txt. Separately, --exclude '???' excluded an NFD src/é directory but deleted dst/É/saved.txt; --exclude '??' excluded src/ſ but deleted dst/s/saved.txt. Before each run, looking up the destination through the source spelling returned the same inode. Every run exited 0.

## Predicted observable failure
Mirror deletes excluded Unicode-equivalent destination subtrees despite the filesystem identifying the spellings as the same entry. Both any-depth glob rules and path glob components remain affected, leaving cr-g3fix5-1 incomplete.

## Reviewer's suggested approach
Preserve the original glob's matching semantics while applying destination equivalence, including normalization, byte-width wildcards, and multi-character mappings. Add deletion-survival coverage for these filesystem-verified pairs.

## Intake
Reproduced 2026-10-18 with the release build of the candidate's code (`blit 1.0.0+df61b1d6464c`, identical product code to `19ace1ac`; script `scratchpad/g3fix6/repro.sh`, output `repro.out`): `--exclude '*ß'` over `src/aß/` deleted `dst/aSS/saved.txt`; `--exclude '??'` over `src/ſ/` deleted `dst/s/saved.txt`; `--exclude '???'` over an NFD `src/é/` deleted the NFC `dst/É/saved.txt` — every run exit 0, `Deleted: 1 file(s), 1 dir(s)`; APFS pairs each source spelling with the destination's (the reviewer confirmed the same inode by lookup). Admitted as HIGH on the same rule. Root cause: no text fold reproduces the filesystem's equivalence while keeping a glob's semantics (`?` counts, byte widths, `ß`→`SS`); cr-g3fix5-1's fold was always an approximation, and the reviewer re-rated the residual as data loss.

## What
Under `mirror`, an entry the source walk excluded protects the destination's own spelling of the same entry — `aSS` for `aß`, `s` for `ſ`, NFC `É` for NFD `é` — by the filesystem's own pairing, with no text folding anywhere; the exclude's glob syntax never has to be re-read under an equivalence.

Fix shape, admitted (the exact mechanism; replaces the fold):
- **The source walk records what it prunes.** Where the enumeration drops an entry because of the exclude rules (`enumeration.rs` ~237 `allows_dir`, and the file-level `allows_entry` rejections; the remote source's `pruning_rules()` path in `remote/transfer/source.rs` ~937 likewise), the entry's relative path, exactly as the source spells it, is recorded with the session as a protected source path — directories and files alike (one path per pruned subtree root, one per pruned file; the set scales with the pruned entries, like the manifest scales with the sent ones).
- **They reach the destination's deletion pass** on every route the pass serves: in process on the local carrier and the pull client; on the wire for a destination daemon through a new repeated field on the message that already carries the manifest's end or the session's filter (`ManifestComplete`, or `SessionOpen` beside `FilterSpec filter = 4` — the agent picks the message the destination has in hand when `mirror_delete_pass` runs), and `CONTRACT_VERSION` (`transfer_session/mod.rs:108`) goes 7 → 8 (1.0 peers refuse other builds at session open anyway; the orchestrator updates the "Wire contract 7" text in the release notes and CHANGELOG).
- **The deletion scope resolves each protected source path at the destination** component by component through `stored_name` (cr-g3fix4-1's identity pairing: the entry the destination filesystem pairs with that spelling, the link itself never its target, every name of a tie), once per path, and protects the resolved entry, its subtree and its ancestors (cr-g3fix5-1's `keep_dirs_holding_left_out_entries`). A path with no destination counterpart protects nothing. FAST: one lookup chain per pruned path, no per-entry cost on the walk beyond a set membership test.
- The textual rules as written and the literal per-directory lookups stay as they are, so a destination-only entry spelled exactly like, or paired by the filesystem with, a LITERAL exclude is still protected. **Residual, recorded in Known gaps and to be stated in the release notes as a limitation:** a destination-only entry (one the source does not have) that a pure-glob exclude would match only under the filesystem's case or normalization equivalence stays in the deletion scope.
- Guards: survival of `dst/aSS` under `*ß`, `dst/s` under `??` (source `ſ`), NFC `dst/É` under `???` (source NFD `é`), each on the local carrier and the destination daemon; a wire test that the protected paths arrive on the daemon route; the three cr-g3fix5 Unicode/glob guards stay green. Mutations: drop the recording → red; drop the wire field → the daemon-route guard red; resolve without `stored_name` → red.

## Approach
- **Mechanism, as admitted: the source walk records what it prunes, the destination resolves it through its own names.** No text folding is added; cr-g3fix5-1's fold is still in this commit and goes in cr-g3fix6-1.
- **Recording** (`enumeration::PrunedPaths`, new). Where the walk drops an entry through its filter — a directory at `allows_dir` (pruned, never opened), a file or symlink at `allows_entry` — it calls `FileFilter::note_pruned` (new), which records the relative path in POSIX form, as the source spells it, when the filter carries a recorder (`FileFilter::pruned`, new, `pub(crate)`). One path per pruned subtree root, one per pruned file; nothing below a pruned directory, which is never read. A name that is not valid UTF-8 is not recorded (the destination resolves by text). The recorder is attached by `FilteredSource` (the one filter chokepoint every session source goes through; its `pruning_rules()` walk at `source.rs` is the remote source's walk too) to the exclude rules alone, so every recorded path is one an exclude named — a size, age or include rejection is never recorded. `FilteredSource::recording_pruned(bool)` (new) switches it on; `SourceScan::take_pruned` (new) hands the set over once the scan finished.
- **Only a mirror of a filtered subset records** (FAST: a copy, a move or a `--delete-scope all` mirror — `MirrorMode::All`, whose deletion scope is unfiltered — records nothing). The session's source half turns recording on from the open (`mirrors_filtered_subset`: `mirror_enabled` and `MIRROR_MODE_FILTERED_SUBSET`) on every wire route (push client, pull and delegated-pull source daemons); the local carrier builds its own `FilteredSource` and turns it on from its own mirror mode (`local.rs`).
- **Wire, contract 7 → 8 — deviation from the admitted shape, with reason.** The admitted shape names a new repeated field on `ManifestComplete` (or `SessionOpen`). One frame cannot carry the set: it scales with the pruned entries (a `--exclude '*.o'` over a large build tree prunes tens of thousands of files), and every session frame is one protobuf message under tonic's 4 MiB decode limit — about 70 000 paths of 60 bytes would make the destination reject the manifest's end and fault the mirror (the summary's own byte budgets exist for the same reason, `remote/transfer/sink.rs`). So the field is `repeated string paths = 1` on a new message `ManifestPruned`, carried by a new frame `TransferFrame.manifest_pruned = 23`, sent by the SOURCE after the walk ended and before `ManifestComplete`, in as many frames as needed, each bounded to 1 MiB of encoded paths (`MAX_PRUNED_FRAME_BYTES`, `pruned_frames`). The set is complete when the walk is, so the destination has all of it in hand when `ManifestComplete` arrives, before the deletion pass. Additive, same-build peers only (`CONTRACT_VERSION` = 8, documented in its version list), no shim. The local carrier runs the same session over its in-process pair, so the same frames carry it there, in process; the pull client is the destination of the daemon's frames.
- **Destination.** `destination_session_inner` accumulates `ManifestPruned` paths (a protocol violation after `ManifestComplete`, or on a session that does not mirror a filtered subset) and passes them to `mirror_delete_pass` (new `pruned` parameter), which hands them to `destination_scope` (new `pruned` parameter).
- **Resolution** (`transfers::filter::resolve_pruned`, `resolve_pruned_on_disk`, `Listings`, new). Once per pruned path, before the deletion walk: one `lstat` of the path as the source spells it (no counterpart: nothing more); otherwise component by component through `stored_name`'s pairing — the exact name, else the entries of the same identity (the link itself, never its target; every name of a tie, sorted; the `canonicalize` fallback for a non-symlink the listing cannot pair). `Listings` applies that pairing with each directory listed, and its entries' identities read, at most once for the whole resolution, so a large directory holding many pruned entries costs one listing, not one per entry; it is dropped after. A path holding a component that names no single entry (empty, `.`, `..`, a root or drive, `\` or `:` on Windows) resolves to nothing. The resolved entries (paths under the destination root) go to `DestinationNames` (new `pruned` field), whose `protects` leaves out an entry in that set and everything below it, checked once per directory of its depth-first chain and once per entry (one set lookup each). Ancestors are kept by cr-g3fix5-1's `keep_dirs_holding_left_out_entries`, unchanged: the resolved entry is left out of the scope, so the directory holding it, and every one above, is dropped from the plan.
- `FileFilter::excluded` now asks `DestinationNames` even when `exclude_files` is empty (an `exclude_dirs` rule also prunes, and is recorded); the as-written checks are unchanged.
- **Unchanged:** the textual rules as written and the literal per-directory lookups (cr-g3fix5-1/-2), so a destination-only entry spelled like, or paired by the filesystem with, a LITERAL exclude is still protected; the CLI (no new option, SIMPLE).
- **What the orchestrator must change in the docs** (not edited here):
  - `docs/RELEASE_NOTES_1_0.md` § Protocol and compatibility, "**Wire contract 7.**" → "**Wire contract 8.**"; `CHANGELOG.md` line 19 ("The wire protocol is contract 7") and line 113 ("Wire protocol (contract 7): …") → contract 8, the latter gaining "a mirror's source names what its excludes pruned (`ManifestPruned`)".
  - `docs/TRANSFER_SESSION.md` § Frame set and field numbers: a table row after 22: "| 23 | `ManifestPruned manifest_pruned` | SOURCE | streaming, before `ManifestComplete`; mirror of a filtered subset only (contract v8) |"; `ManifestPruned` joins the list of new session messages under the table, and a paragraph after the `ManifestComplete … scan_failures (v7, cr-ssc6-1)` paragraph (end of § Phase state machine): what the frame carries, when it is sent, the 1 MiB-per-frame batching, that the destination resolves each path through its own names and keeps the entry, its subtree and its ancestors out of the deletions, and that it is a protocol violation after `ManifestComplete` or on any other session. The state-machine line "SOURCE streams: ManifestEntry* ... ManifestComplete" becomes "ManifestEntry* ManifestPruned* ManifestComplete". The sentence "No delete list crosses the wire" stays true (it is a keep list).
  - `docs/RELEASE_NOTES_1_0.md` § Known limitations shipped open, a new bullet: "**A `mirror` exclude written as a pure glob keeps a destination-only entry only in the spelling it matches as written.** An entry the source has is kept in whatever spelling the destination's filesystem stores it (`aSS` for an excluded `aß` on macOS); an entry only the destination has, which the glob would match only under the filesystem's case or Unicode equivalence (`dst/bSS` under `--exclude '*ß'` with no `bß` in the source), is deleted. A literal name, or a literal component of a path exclude, is matched in the destination's own spelling either way."

## Known gaps
- **Residual, recorded as a limitation (release notes, above):** a destination-only entry — one the source does not have, so its walk pruned nothing of that name — that a pure-glob exclude would match only under the filesystem's case or normalization equivalence stays in the deletion scope (`dst/bSS` under `--exclude '*ß'` with no `bß` in the source). The rules as written and the literal lookups still protect the exact spelling and any literal's paired spelling.
- A pruned name that is not valid UTF-8 is not recorded, so a destination spelling the filesystem pairs with it is not protected by this mechanism (the rules as written still apply).
- Both ends hold the pruned set in memory for the session (proportional to the pruned entries, like the manifest's own source set at the destination); the resolution's listings are held only while it runs.
- A `--files-from` scope bypasses the excludes, so nothing is pruned or recorded (unchanged semantics).
- The delegated pull (daemon to daemon) runs the same session code (its source daemon records, its destination daemon resolves) but no guard drives that topology.
- Platforms: run on macOS aarch64 (APFS, case-insensitive) only, plus the Linux and Windows cross-clippy at the gate. On Linux ext4 P3's pairing, P4, P7, P8 and P9 skip with a message (ext4 pairs none of the spellings), so they can go red only on a pairing filesystem; P1, P2, P5, P6 run and can go red everywhere. On Windows (NTFS) P7 runs only the cases NTFS pairs (not verified here; NTFS does not normalize, so NFD skips), and P8/P9 are Unix-only like the other daemon tests.
