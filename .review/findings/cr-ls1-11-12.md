## cr-ls1-11 — the remote-pin guard did not guard route dispatch

> `transfers/mod.rs:811` tests `reject_unsupported_checker_pin` directly
> rather than exercising `run_transfer_inner` or `run_move_inner`. I disabled
> both production calls at lines 305 and 544 and the intended test remained
> green, so the claimed guarantee that every remote route refuses the
> diagnostic pin can regress unnoticed. Test through the dispatch or CLI
> boundary.

**Eighth vacuous guard in this slice.** The pattern is now fully explicit:
each time, the assertion tests the piece I just wrote rather than the seam
where it is USED, so deleting the usage leaves it green. cr-ls1-8 was the
parallel iterator; cr-ls1-9 was the pool wiring; this is the gate wiring.
Three instances of one mistake, caught three times by someone else.

### Fix

`the_dispatch_refuses_a_checker_pin_it_cannot_honour` drives
`run_transfer_inner` (Copy and Mirror) and `run_move_inner` with a remote
endpoint, and asserts the refusal names the flag and the remedy. The gate
fires before any RPC, so no network is required. It also asserts the
opposite direction — `checkers: 0` must NOT be refused — so the gate cannot
degrade into "reject all remote transfers" and still pass.

**Guard proof**: commenting out BOTH production call sites (exactly what the
reviewer did) reds it with
`Copy must refuse with a message naming the flag and the remedy`. Restored,
byte-identical SHA-256 (`B8BDDF59…B07D`), green after.

## cr-ls1-12 — the pin was rejected after user-visible startup actions

> The new checks run only after the starting banner and, for mirror/move,
> after destructive confirmation. An invalid remote copy therefore prints
> "starting" before failing, while mirror/move can prompt for an operation
> that cannot run.

Correct, and the mirror/move half is the part that matters: the operator was
being asked to authorise deleting extraneous files — or deleting the source —
for a command that was always going to fail. Consent obtained for an
operation that cannot happen is a bad shape regardless of outcome.

### Fix

Both checks move up beside the existing `--null` and `--detach` route gates,
immediately after route resolution and before any banner, warning or prompt.
The helper now takes the route and makes the local-route exemption itself,
so the call site is a single unconditional line and cannot be given the
wrong condition at one of two sites.
