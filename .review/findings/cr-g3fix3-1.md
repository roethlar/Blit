## Evidence
crates/blit-core/src/transfers/filter.rs:565 — paired_name uses Unicode lowercase rather than filesystem equivalence; when pairing fails, stored_name returns None for symlinks at line 535. Reproduced on case-insensitive macOS with src/σ pointing outside the source and absolute exclude src/ς: both paths had the same symlink inode, but local and wire patterns remained ./ς with no warning. Mirror deleted dst/σ/saved.txt and its directory. An NFD-stored café symlink excluded using uppercase NFC CAFÉ behaved identically. Exact stored-spelling controls preserved both destination subtrees.

## Predicted observable failure
A valid absolute exclude naming an existing symlink through another filesystem-equivalent spelling silently fails to protect its destination counterpart; mirror deletes pre-existing data. This leaves cr-g3fix2-1 and cr-g3fix-1 materially open.

## Reviewer's suggested approach
Recover the entry's stored name using filesystem-aware lookup or candidate identity checked without following symlinks. Cover Unicode case equivalence and normalization with destination-survival tests.

## Intake
Admitted; reproduced by the orchestrator with the release binary `blit 1.0.0+36b752b6ff1e` on macOS APFS: `src/σ -> <outside>`, `blit mirror -y src/ dst/ --exclude <src>/ς` printed no warning and reported "Deleted: 1 file(s), 1 dir(s)" — `dst/σ/saved.txt` and its directory gone. This is the gap cr-g3fix2-1's Known gaps recorded ("case folding is per-character Unicode lowercase, not the filesystem's own table"), and it is a data-loss path under `mirror`, so it cannot stay a gap. Root cause: `paired_name` (`filter.rs:565`) decides equivalence by text (per-character lowercase), but the filesystem's rule is what made the typed path resolve — APFS pairs final sigma with sigma and NFC with NFD; no text rule reproduces every filesystem's table. Fix shape (the reviewer's "candidate identity checked without following symlinks"): let the filesystem decide. `symlink_metadata(typed)` already proves the typed path denotes an entry without following it; pair it with the parent listing's entry that has the same identity under `symlink_metadata` — on Unix `(dev, ino)` via `std::os::unix::fs::MetadataExt` — the link itself, never its target. Order: the entry spelled exactly as typed (no stat) → otherwise walk the listing and `symlink_metadata` each entry until the identity matches (stop at the first hit; a hard-linked identity that matches several entries takes the fold-equal one, else pairs nothing). This replaces text folding on Unix; on Windows std has no stable file identity (`file_index` is unstable), and NTFS equivalence is an upcase table with no normalization rule, so the case-fold pairing stays there and is recorded as the remaining gap. Guards: the stored-name unit test and the case guard gain a `σ` symlink excluded as `ς` and an NFD `café` symlink excluded as NFC `CAFÉ`, each run only where the filesystem pairs them (probe at test time: create `σ`, `symlink_metadata(ς)` succeeds), the pattern becoming `./σ` / `./café` (NFD) in both `build` and `build_spec`; a CLI `mirror` destination-survival test for the sigma case; a pure test of the identity pairing against a stand-in listing (exact wins, identity next, several identities need the fold, none pairs nothing); all mutation-red. Cost note (FAST): the identity walk is one `lstat` per listed entry until the hit, only when no entry is spelled as typed, once per absolute exclude component — not on the transfer's per-entry path.

## What
On Unix an absolute `--exclude` that names a symlink in a spelling the filesystem accepts but the disk does not store now names the link as stored. Examples are final sigma `ς` for a stored `σ`, or NFC `CAFÉ` for a stored NFD `café` (both on APFS). The pattern becomes `./σ` or `./café` (NFD) in the local rule and in the wire form, the link is left out, and under `mirror` the destination's `σ/` subtree stays outside the deletion scope. Before, the pairing was per-character Unicode lowercase, which pairs neither. The exclude stayed `./ς`, matched nothing, warned about nothing, and `blit mirror -y` deleted `dst/σ/saved.txt` with its directory.

## Approach
- The filesystem decides, not a text rule. `stored_name` already proves with `symlink_metadata(typed)` that the typed path denotes an entry, without following it. It now passes that metadata to `listed_name`, which pairs it with the parent listing's entry that has the same identity.
- `listed_name` (`filter.rs`) reads the parent's listing once into a list of names, then on Unix calls `paired_name` with the typed path's identity `(dev, ino)` (`std::os::unix::fs::MetadataExt`). Each candidate is tested with `symlink_metadata(parent/name)`, which compares the link itself, never its target. On other platforms it calls `paired_by_case`.
- `paired_name` (rewritten, pure; the identity test is a closure):
  1. The entry spelled exactly as typed wins, with no lookup.
  2. Otherwise the listing is walked and the first entry with the typed path's identity wins; the walk stops there.
  3. When the identity can have several names in the listing (`shared`: a non-directory with `nlink > 1`, i.e. a hard-linked file), the whole listing is walked. Several matches pair the only one of them that is fold-equal to the typed name; none, or several fold-equal, pair nothing. One match pairs it.
  4. No match pairs nothing.
- `paired_by_case` is cr-g3fix2-1's exact-else-single-case-fold rule, kept for Windows, where std has no stable file identity (`MetadataExt::file_index` is unstable) and NTFS's equivalence is its upcase table with no normalization. `single_fold` (per-character Unicode lowercase; exactly one match or none) is shared by the Windows rule and the hard-link tie-break. `paired_name` is compiled `cfg(any(unix, test))` and `paired_by_case` `cfg(any(not(unix), test))`, so both pure rules are tested on every OS and neither is dead code on its platform.
- On Unix this replaces the text folding: the case pairing cr-g3fix2-1 needed (`LINK` → `link`) now comes from identity as well, and its guards stay green.
- `stored_name`'s fallback to `canonicalize` (for a non-symlink the listing cannot pair) is unchanged. On Unix it now matters only when the listing cannot be read.
- Cost (FAST): unchanged when an entry is spelled as typed (one directory read, no stat). Otherwise there is one `lstat` per listed entry until the hit, or the whole listing for a hard-linked file. That happens once per typed component of an absolute exclude, when the filter is built, never on the transfer's per-entry path.
- No deviation from the admitted fix shape. Reconciling the shape's "first hit wins" with "a hard-linked identity that matches several entries takes the fold-equal one": the walk can only know there are several by continuing. So it stops at the first hit unless the typed entry's own `nlink` says its identity can have several names.

## Known gaps
- Windows keeps the case-fold pairing (per-character Unicode lowercase), not NTFS's upcase table, because std has no stable file identity there. A symlink typed in a spelling only NTFS pairs (for example `ς` for `σ`, both of which NTFS upcases to `Σ`) keeps its typed spelling and matches nothing; a non-symlink still takes its stored name from `canonicalize`. That is what remains of the gap cr-g3fix-1 and cr-g3fix2-1 recorded, narrowed to Windows symlinks.
- A hard-linked file typed in a spelling only the filesystem pairs, when several of its names are in the listing and none or several are fold-equal to the typed name, pairs nothing and keeps its typed spelling.
- A directory is assumed to have one name in its parent's listing, so the first identity match wins. A bind mount of a directory onto a sibling in the same parent (Linux) shares its identity, and the first one listed would win. This can only arise when no entry is spelled as typed, which on Linux needs a case- or normalization-insensitive filesystem.
- Observation, unchanged (cr-g3fix2-1): the destination's own spelling is never consulted. Under `mirror`, a destination entry stored in a third spelling is not named by the source's stored spelling.
- I1, I2's symlink entries and I4 are Unix-only (making a symlink on Windows needs privilege) and run only where the filesystem pairs the spellings: macOS APFS here; on Linux CI (case-sensitive ext4) they print a skip line and pass, so they can go red only on such a filesystem. I3 and I5 run everywhere. Windows behaviour of `paired_by_case` is by its pure test and by reading.
- Verified on macOS aarch64 only, plus the Linux and Windows cross-clippy at the final gate; Linux and Windows runtime tests were not run here.
